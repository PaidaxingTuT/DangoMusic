# v1.6.2 用户反馈修复记录

用户已确认 v1.6.2 可正常使用，并反馈：歌单封面获取不到、首页推荐太少、我的歌单应按添加时间倒序。随后通过“修 todo”授权实施。

本次范围：酷狗标准版与概念版，共用 `BaseKugouApi` 实现。

## 已实现

- [x] 歌单封面：兼容 `flexible_cover`、`pic`、`imgurl`、`cover`、`img`、`sizable_cover` 及 `trans_param.union_cover`；补全 `stdmusic/`、`custom/`、`soft/collection/` 相对路径和协议省略地址，替换 `{size}`。
- [x] 无独立封面的非空用户歌单：读取首批最多 10 首歌曲，使用其中首个可用的封面；补图请求失败时保留歌单，空歌单不请求补图。
- [x] 首页推荐：改用 `/v2/special_recommend`，请求 30 条并接收接口附带的额外推荐；按歌单 ID 去重，优先使用 `flexible_cover`，避免拿到作者头像。新接口失败或返回空列表时回退旧首页接口。
- [x] 我的歌单：分页全部读取后统一按 `collecttime`、`addtime`、`add_time`、`create_time` 的首个有效时间倒序排列；兼容秒和毫秒，同一时间维持原顺序，缺失时间放最后。
- [x] 侧栏“我喜欢”图标：识别实际标记或名称，避免排序后误把最新歌单显示成“我喜欢”。

## 验证与边界

- 公共模块 14 项回归测试通过，包括跨页排序、时间单位、备用封面、补图失败和专用推荐请求；两个酷狗平台分别覆盖。
- 实际请求专用推荐接口，标准版和概念版均返回 35 个歌单，推荐封面下载均为 `200 image/jpeg`。
- 当前“我的歌单”时间字段依据本地 EchoMusic 接口映射确认，未使用真实登录账号完成游戏内排序及自建歌单补图实测。
- 缺少封面且首批歌曲也没有可用封面的歌单继续显示占位图；缺少添加时间时无法推断真实时间，保留接口顺序。
